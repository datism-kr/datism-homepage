# 브랜드 자산 · 저작권 정본

`datism.kr`이 쓰는 로고·서체의 출처, 라이선스, 사용 규정을 한 파일로 모은 정본이다.
자산을 추가하거나 라이선스가 바뀌면 **여기부터 고친다**.

최종 갱신: 2026-08-05

---

## 1. 마크 (심벌)

| | |
|---|---|
| 형태 | D를 관통하는 화살 |
| 위치 | `index.html`·`privacy.html` 상단바에 인라인 SVG, 파비콘에 data URI |
| 저작권 | 데이티즘 주식회사 자체 제작 · 전부 보유 |
| 색 | 단색. `currentColor`를 타므로 라이트/다크에서 자동 반전 |

파비콘은 외부 파일 없이 인라인 data URI로 넣었다 — 요청 1회를 아끼고, 자산 경로가 깨져도
아이콘이 사라지지 않는다.

## 2. 워드마크 (활자부) — 두 벌 운용

**Space Grotesk** 글리프를 패스로 확정한 아웃라인 두 벌이다. 굵기 대역이 다를 뿐 같은 서체라
형태가 어긋나지 않는다.

| | `assets/wordmark_S.svg` | `assets/wordmark_L.svg` |
|---|---|---|
| 컷 | 볼드 | 라이트 |
| viewBox | `-2 -2 346.4 76.801` (4.510:1) | `-2 -2 340.3 76.801` (4.431:1) |
| 획 두께 (I 스템) | 캡하이트의 15.4% | 캡하이트의 9.1% |
| **최소 높이** | **16px** | **28px** |
| 용도 | 상단바, 파비콘, 앱 아이콘, 스토어 배너, 본문 인라인 | 푸터 사인오프, 히어로, OG 이미지, 명함, 인쇄 |

### 좌표계 — `height`는 글자 높이가 아니다
두 파일 모두 캡하이트 70, 원본 상하 여백 1.4, viewBox에 사방 2 여백을 더했다. 따라서

```
글자 실높이 = CSS height × (70 / 76.801) ≒ height × 0.911
```

상단바 `height: 19px` → 글자 17.3px, 푸터 `height: 41px` → 글자 37.4px. 크기를 조정할 때
이 환산을 잊으면 마크와 시각 높이가 어긋난다.

viewBox의 사방 2 여백은 장식이 아니다 — 원본에 `stroke-width: 0.25mm` 아웃라인이 얹혀 있어
여백이 0이면 글자 가장자리가 반 픽셀 잘린다.

### 왜 폰트로 조판하지 않고 패스로 고정했나
워드마크를 웹폰트로 조판하면 ① 폰트 로딩 실패 시 로고가 다른 글꼴로 바뀌고 ② OS·브라우저마다
자간이 미세하게 달라진다. 패스로 확정하면 두 문제가 사라진다 — 사이트가 Space Grotesk를
로드하지 않아도 워드마크는 항상 같은 모양이다.

### 사이트에서 색을 입히는 방법
`<img>`가 아니라 **CSS 마스크**로 얹는다. 그래야 `currentColor`를 타고 다크 모드가 자동으로
따라온다 (`style.css` §3):

```css
.wordmark-type {
  height: 21px;
  aspect-ratio: 604 / 120;
  background: currentColor;
  mask: url('assets/wordmark_S.svg') no-repeat center / contain;
}
```

### 마크와의 록업 (푸터 사인오프 — 2026-08-06 폐지)
푸터의 마크+워드마크 사인오프는 제거했다. 지금 화면에서 로고가 나오는 곳은 **상단바 하나**다.

따라서 **L컷은 화면에서 쓰이지 않는다.** 파일은 남겨 둔다 — OG 이미지·명함·인쇄처럼 크게
쓰는 자리가 L컷 담당이고, `_preview/proof.html`도 그 규격을 검수한다.

### 인트로 시퀀스에서의 록업 (index.html 진입 연출)
마지막 비트에서 마크가 왼쪽으로 들어와 `D`와 붙는다. 여기서는 록업 규격이 푸터와 다르다 —
글자가 크고 화면 정중앙에 놓이기 때문에 푸터에서는 안 보이던 편차가 드러난다.

인트로의 라틴 글자는 **Space Grotesk 700**으로 조판한다(§3-3). 워드마크가 바로 그 글자꼴의
아웃라인이므로, 마지막 비트에서 `D`가 그대로 로고가 되는 연결이 서체까지 이어진다.
인트로 최종 록업은 **S컷(볼드)**을 쓴다 — 인계 대상인 상단바도 S컷이라 굵기가 튀지 않는다.
L컷은 푸터 사인오프 전담이다.

| | 값 | 이유 |
|---|---|---|
| 마크 높이 | `0.945em` | 내용이 박스의 74.1%이므로 실제 그림이 0.700em → Space Grotesk 캡하이트(0.700em, 실측)와 일치 |
| 마크 수직 보정 | `top: -0.0413em` | 마크 SVG는 내용이 아래로 치우쳐 있다(위 여백 17.3% · 아래 8.6%). 박스를 맞추면 그림이 낮게 보인다. 보정량 = 0.0437 × 높이 |
| 최종 록업 수평 보정 | `margin-left: -0.846em` | 마크 왼쪽 여백이 오른쪽보다 넓어, 기하학적 중앙에 두면 8~9px 오른쪽으로 쏠려 보인다 |
| 자간 | `-0.024em` | 눈대중이 아니다. `wordmark_S`의 글자부는 캡하이트 70에서 폭 342.4인데 Space Grotesk 700 기본 자간은 357이 나온다 — 그 차이를 글자 수로 나눈 값, 즉 로고에 박힌 자간의 재현 |

**글자꼴을 바꾸면 위 세 값을 다시 계산해야 한다.** SUIT ExtraBold를 쓰던 시절 값은
각각 `0.98em` / `-0.043em` / `-0.035em`이었다 — 캡하이트가 0.735em이었기 때문이다.

상단바·푸터 록업에는 이 세 보정을 넣지 않는다 — 마크가 작아 편차가 2~3px이고, 셋의 규격을
서로 맞추는 편이 유지보수에 낫다. 큰 크기에서만 보정한다.

### 사용 규정
- **최소 크기를 지킨다.** L컷을 28px 미만으로 쓰면 얇은 획이 뭉개진다 — 그 대역은 S컷 담당이다.
- **비율을 고정한다.** `aspect-ratio`로 잡고 임의로 늘리거나 좁히지 않는다.
- **여백**: 워드마크 캡하이트의 절반 이상을 사방에 비운다.
- **색**: 단색만. 그러데이션·외곽선·그림자를 얹지 않는다.
- 파일을 교체할 때는 viewBox 비율이 바뀌므로 `style.css`의 `aspect-ratio`도 반드시 같이 고친다.

## 3. 서체

### 3-1. 제목 — SUIT ExtraBold

| | |
|---|---|
| 제작 | SUNN (sun.fo/suit) |
| 라이선스 | SIL Open Font License 1.1 |
| 저작권 | Copyright (c) 2022, SUNN, with Reserved Font Name SUIT |
| 라이선스 원문 | `assets/fonts/SUIT-OFL.txt` (저장소에 동봉) |
| 파일 | `assets/fonts/SUIT-ExtraBold.woff2` (168KB) — **자체 호스팅** |
| 쓰는 웨이트 | 800 하나 |

**왜 자체 호스팅인가.** 가변폰트 전체는 610KB인데 우리는 800 한 웨이트만 쓴다. 정적 컷
168KB만 받아 저장소에 두면 용량이 1/4이고, CDN이 죽어도 브랜드 서체가 뜬다.
`font-display: swap`이라 폰트를 받는 동안 글자가 사라지지 않는다.

**OFL 의무 이행.** 폰트 파일을 저장소에 담아 배포하므로 라이선스 원문 동봉이 필요하다 —
`assets/fonts/SUIT-OFL.txt`가 그것이다. 이 파일을 지우면 안 된다.

### 3-2. 본문 — Pretendard Variable

| | |
|---|---|
| 제작 | 길형진 (orioncactus) |
| 라이선스 | SIL Open Font License 1.1 |
| 저작권 | Copyright (c) 2021 Kil Hyung-jin, with Reserved Font Name Pretendard |
| 조달 | jsDelivr CDN (`pretendard@v1.3.9` dynamic-subset) — 파일을 저장소에 두지 않음 |

**왜 CDN인가.** Pretendard 동적 서브셋은 `unicode-range`로 92조각으로 쪼개져 있어, 브라우저가
그 페이지에 실제로 쓰인 글자가 든 조각만 내려받는다. 자체 호스팅하면 그 장점이 사라진다
(파일 92개를 전부 저장소에 넣어야 한다). 폰트를 재배포하지 않으므로 원문 동봉 의무도 없다.

### 3-3. 로고 · 라틴 태그라인 — Space Grotesk Variable

| | |
|---|---|
| 제작 | Florian Karsten |
| 라이선스 | SIL Open Font License 1.1 |
| 저작권 | Copyright 2020 The Space Grotesk Project Authors |
| 라이선스 원문 | `assets/fonts/SpaceGrotesk-OFL.txt` (저장소에 동봉) |
| 파일 | `assets/fonts/SpaceGrotesk-Variable.woff2` (22KB, 라틴 서브셋, 300~700) — **자체 호스팅** |
| 쓰는 곳 | 인트로 전체, `.aim-kicker`, `.eyebrow` — 즉 화면의 모든 라틴 태그라인 |

**왜 자체 호스팅인가.** 워드마크 SVG가 바로 이 글자꼴의 아웃라인이다. 로고와 한 벌로 읽혀야
하는 서체가 CDN 사정에 매달리면 안 되고, 인트로 첫 글자가 이 서체라 늦게 오면 `A`가 다른
글꼴로 한 번 그려진다. 라틴 서브셋 가변폰트가 22KB뿐이라 자체 호스팅 비용이 사실상 없다.
`<head>`에서 `preload`한다.

**OFL 의무 이행.** 폰트 파일을 저장소에 담아 배포하므로 원문 동봉이 필요하다 —
`assets/fonts/SpaceGrotesk-OFL.txt`. 이 파일을 지우면 안 된다.

### 3-4. OFL 1.1 요약 (세 서체 공통)

- **허용**: 상업적 사용, 임베딩, 수정, 재배포 — 무료·유료 제품 모두. 별도 비용·신고 없음.
- **의무**: 폰트 파일 자체를 (수정본 포함) 배포할 때 저작권 표시와 라이선스 전문을 함께 둘 것.
- **금지**: 폰트를 단독 상품으로 판매하는 것. 예약 폰트명(Reserved Font Name — `SUIT`,
  `Pretendard`)을 그대로 단 수정본을 배포하는 것.
- 폰트로 조판한 **결과물**(웹페이지·이미지·인쇄물)에는 아무 제약이 없다. 폰트 아웃라인으로 로고를
  만드는 것도 OFL상 문제없지만, 우리 워드마크는 애초에 자체 작도라 이 조항과 무관하다.

### 3-5. 교체 이력

2026-08-05, `Jua`(제목) + `Gowun Dodum`(본문) → `SUIT ExtraBold` + `Pretendard`.
둥근 손글씨 계열이라 법인 정보(사업자등록번호·주소)가 놓이는 자리에서 신뢰 신호가 약했다.
두 구 서체도 OFL 1.1이라 되돌리는 데 라이선스상 제약은 없다.

### OG 카드 만들기
카카오톡·페이스북 링크 카드에 뜨는 이미지다. 생성 스크립트의 요지:

- 워드마크 SVG가 **정본**이므로 폰트로 다시 조판하지 않고 **패스를 직접 래스터라이즈**한다
  (M/L/Q/C/Z 절대좌표만 쓴다). `D`·`A`의 구멍은 서브패스 마스크를 XOR해서 뚫는다(even-odd).
- 별은 사이트 하늘(viewBox 1200×800)의 가운데 630 띠를 그대로 가져온다 — 첫 화면과 같은 별자리다.
- 록업 비례는 푸터 규격과 같다(마크 1.537H × 1.122H, 워드마크 높이 H, gap 0.30H).
  마크 왼쪽 여백이 넓어 기하학적 중앙에 두면 오른쪽으로 쏠리므로 시각 보정을 뺀다.

**이미지를 고치면 파일명을 바꾼다.** 카카오·페이스북은 이미지 URL로 캐시해서, 같은 경로에
덮어쓰면 옛 카드가 계속 나온다. 카카오는 그 위에 자체 캐시가 또 있어 개발자 도구의
캐시 초기화가 필요할 수 있다.

## 5. 하지 말 것

1. 워드마크를 폰트로 다시 조판하기 — 아웃라인 SVG가 정본이다.
2. S컷과 L컷 중 한쪽만 교체하기 — 굵기만 다른 한 벌이라 형태가 어긋난다.
3. SVG를 갈아끼우면서 `style.css`의 `aspect-ratio`를 안 고치기 — 글자가 늘어난다.
4. `assets/fonts/SUIT-OFL.txt` · `SpaceGrotesk-OFL.txt` 삭제 — OFL 의무 위반이 된다.
5. 최소 크기(S 16px / L 28px) 아래로 축소.
6. `height`를 글자 높이로 착각하기 — 박스 높이다(§2 좌표계 참조).

## 7. 스크롤 씬 (index.html)

한 화면에 정보 하나씩 놓는 구성이다. 뷰포트보다 긴 `.scene` 안에 `sticky` 무대를 두고,
섹션 안에서의 스크롤 진행률로 연출을 몰아간다.

| 씬 | 길이 | 면 | 연출 |
|---|---|---|---|
| `#top` | 1.5화면 | 밤 인디고 | 조준선(0~0.24) → 화살을 걸고 당김(0.24~0.40) → **발사**(0.40~0.475) → 명중(~0.53) → 파열(0.50~0.86) → 암전 |
| `#tamsadae-z` | 4.4화면 | 먹빛 | **한 무대에 세 장**(아래 덱 참조) |

### 티저는 별도 사이트다
`tamsadae.datism.kr`은 **Cloudflare에 올라간 별도 저장소**(`datism-kr/tamsadae-landing`)다.
GitHub Pages가 아니므로 이 저장소와 아무 관계가 없다. 첫 화면의 별빛 버튼이 그리로 보낸다.

그 사이트는 **`noindex, nofollow` + `robots.txt` 전체 차단**인 비공개 단계다(R1 플레이테스트
전까지). 따라서 **사이트맵에 넣지 않고, 같은 내용을 datism.kr 쪽에 다시 만들지 않는다** —
색인되는 중복 페이지가 생기면 그쪽의 비공개 결정과 어긋난다.

### 제품 덱 — 한 무대에 세 장
초판은 제품 씬이 셋으로 나뉘어 있었다(소개·기록·분기). 배경이 매번 새로 스크롤돼 올라와
"긴 페이지를 내려간다"로 읽혔다. 지금은 **하나의 sticky 무대**에 세 장을 포개고, 배경(흐린
플레이 화면)은 고정한 채 앞의 판만 교체한다 — 배경이 안 움직이므로 "다음 슬라이드"가 된다.
가로 스크롤 하이재킹의 감각을 그 부작용 없이 얻는 자리다.

| 판 | 구간(씬 진행률) | 내용 |
|---|---|---|
| `intro` | 0.00–0.28 | 제품 소개 + 티저 버튼 |
| `record` | 0.28–0.66 | ■ 막대가 흩어진 상태 → 모임 → 문장으로 풀림 |
| `branch` | 0.66–1.00 | 선택 두 갈래 사이로 무게 이동 |

판마다 **자기 몫의 진행률 `q`(0~1)**로 연출한다 — 그래서 각 판의 연출 코드는 구간을 몰라도
된다. 경계에서는 `FZ = 0.06`만큼 겹쳐 교차하고, 나가는 판은 위로 들어오는 판은 아래에서
들어온다(세로 한 방향).

`data-hold="0.28 0.58 0.66 0.90"` — 판이 바뀌는 자리와 각 판의 내용이 완성된 자리에서
멈춘다. JS가 없으면 `.deck`이 그냥 세로 흐름이라 세 장이 차례로 읽힌다.

`--len`은 **연출이 다 돌아가는 데 필요한 스크롤 양**을 정한다. 1.0이면 이동 구간이 0이라
연출이 통째로 건너뛰어지므로 1.3 아래로는 내리지 않는다. 초판은 2.2/1.9/2.2/2.2(전체 10.1화면)
였는데 손가락을 너무 많이 밀어야 해서 위 값으로 줄였다(전체 7.1화면).

높이는 `vh`가 아니라 **`svh`**로 잡는다(`@supports`로 감쌌다). 모바일에서 `100vh`는 주소창이
펼쳐진 큰 높이라, 스크롤 중 주소창이 접혔다 펴질 때마다 무대가 출렁인다.

### 씬 이음매를 지우는 베일
어두운 씬은 끝에서 먹빛으로 잠기고, 다음 씬은 **화면으로 올라오는 동안** 그 먹빛에서
밝아진다(`.scene-veil`). 경계선이 안 보이므로 탭 한 번이 "다음 슬라이드"로 읽힌다.

**시작 페이드를 `p`로 계산하면 안 된다.** `p`는 섹션 머리가 화면 위를 지난 뒤에야 0에서
오르는데, 탭이 내려놓는 자리가 정확히 그 `p=0` 지점이다 — 그래서 초판은 탭할 때마다
완전히 검은 화면에 착지했다(실제로 난 사고다). 지금은 "섹션이 아래에서 얼마나 올라왔는가"
(`(vh - rect.top) / (vh × 0.7)`)로 재므로 착지 시점에는 항상 다 걷혀 있다.

끝 페이드도 마지막 12%(`p 0.88~1`)에서만 돈다. 그전에 시작하면 아래 `data-hold`로
붙잡아 둔 문장이 가려진다.

### 탭으로 다음 화면 (터치 기기)
빈 곳을 탭하면 **다음 섹션 머리**로 미끄러진다. 탭 한 번이 그 씬을 통째로 재생한다.
초판은 씬마다 "연출이 끝나는 지점"을 정지점으로 하나 더 뒀는데, 그러면 첫 탭이 암전된
상태에서 멈추고 한 번 더 눌러야 넘어가 번거로웠다.

씬에 `data-hold="0.82"`가 있으면 그 씬 안에 **한 번 더 멈추는 자리**가 생긴다. 내용이
스크롤로 완성되는 씬만 갖는다 — `#record`(지워진 막대 → 풀린 문장)와 `#branch`(갈래 1 →
갈래 2). 이걸 안 두면 탭이 그 씬을 통과해 버려서 정작 만들어낸 문장을 아무도 못 읽는다.
결과적으로 첫 화면은 탭 한 번에 통째로 지나가고, 뒤 씬들은 차근차근 나온다.

`data-hold` 값은 그 씬의 연출이 끝나는 시점보다 뒤, 끝 페이드(0.88)보다 앞이어야 한다.
`#record`의 문장은 `p=0.78`에 다 풀리도록 맞춰져 있다.

스크롤은 브라우저 기본 `smooth`가 아니라 **직접 굴린다**(`glide`). 기본 구현은 길이도
곡선도 브라우저마다 달라 씬 하나가 눈 깜짝할 사이에 지나가기도 한다. 거리에 비례해
460~1100ms(easeInOutCubic)를 잡고, 그 시간만큼 연타를 잠근다 — 활공 중에 또 눌리면
중간 위치를 기준으로 다음 칸을 잡아 두 칸이 넘어간다.

`touchstart`가 아니라 **`click`**으로 잡는 게 핵심이다. 스크롤 제스처는 click을 만들지 않으므로
밀어 넘기는 동작과 탭이 저절로 구분된다. 링크·버튼·입력·인트로 위의 탭은 무시하고, 글을 긁어
놓은 상태에서도 움직이지 않으며, 450ms 안의 연타는 한 번으로 친다(더블탭 확대 대비).
안내 문구는 첫 화면에만 뜨고 한 번 쓰면 사라진다. `?tap=1`로 마우스 환경에서도 켜서 검수한다.

`#top`의 하늘 좌표는 viewBox에 고정하지 않고 **지금 실제로 보이는 viewBox 구간**을 구해
그 안의 비율로 배치한다(`layoutAim`). `preserveAspectRatio="slice"`라 세로 화면에서는
좌우가 잘려 나가 — 고정 좌표로 두면 375px 폭에서 별과 화살이 통째로 화면 밖이었다.

**별은 키커 바로 위**에 선다. 하늘 SVG와 카피는 좌표계가 달라서, 키커의 화면 좌표를
viewBox 좌표로 되돌려 넣는다. 이 위치는 글꼴이 들어와야 확정되므로 `document.fonts.ready`
이후 한 번 더 계산한다 — 한 번만 잡으면 대체 글꼴 기준 좌표가 그대로 굳는다.

발사가 "팍" 하고 느껴지는 건 **대비** 때문이다. 당김은 0.16 구간을 쓰고 비행은 0.075
구간에 끝난다 — 절반의 시간에 열 배의 거리를 간다. 당기는 동안 조준선이 진해졌다가(장력)
화살이 떠나면 툭 끊기고, 비행 중에는 화살이 진행 방향으로 1.5배까지 늘어난다.

**명중 뒤에는 암전이 다음 씬으로 잇는다.** 별이 바닥으로 떨어져 빛무리(웅덩이)를 남기던
초판은 폐기했다 — 화면이 지저분해지고, 다음 씬이 어차피 먹빛이라 같은 색으로 덮는 편이
경계를 아예 없앤다. `.aim-fade`는 0.96까지만 간다(1.0이면 마지막 한 프레임이 빈 화면이다).

### 왜 ■인가
■는 『탐사대 Z』의 서명 장치(괴담에 잠식된 고유명을 지운다)다. 그래서 이 화면은 추상 도형이
아니라 **지워진 말**로 읽힌다 — 도형이 글자로 바뀌는 데 명분이 있다. 떠다니는 말풍선 같은
남의 장치를 빌리지 않고 같은 문법을 우리 소재로 푼 자리다.

### 손대면 깨지는 값
- `.rd-b`의 `top: 0.42em` / `height: 0.82em` — 막대가 가리는 글자의 잉크 띠 좌표다.
  `.redact`의 `font-size`·`line-height`를 바꾸면 이 두 값을 다시 계산해야 한다.
- 분기 흐림 하한 `0.66` — 그 아래로 내리면 고르지 않은 쪽 결과문이 WCAG AA 밑으로 떨어진다.
- `--sc-mark`는 바탕과 2.9:1이다. 더 어둡게 하면 첫 화면이 비어 보인다.
- 씬은 어느 경우에도 **본문을 숨기지 않는다**. JS 미작동·모션 감소면 평범한 한 화면짜리
  섹션으로 읽히고, 크롤러가 보는 것도 그 상태다.

### 상단 메뉴
`데이티즘 소개`(/about/) · `프로덕트`(#tamsadae-z) · `채용`(/careers/).
구 `제품·회사·문의`보다 이름이 길어 460px 아래에서 한 단계 조인다 — `.nav a`의
`white-space: nowrap`을 지우면 글자 단위로 쪼개진다.

## 8. 색 — 밤 인디고 + 별빛 앰버

로고는 활에 화살을 건 D다. 거기서 "멀리 있는 별을 오래 겨냥해 결국 떨어뜨린다"를 읽어
회사 색을 정했다. **차가운 넓은 면 + 따뜻한 점 하나** 구조다.

| 토큰 | 값 | 쓰임 | 대비(바탕 위) |
|---|---|---|---|
| `--nt-bg` | `#151C3F` | 밤하늘 면 | — |
| `--nt-deep` / `--nt-rise` | `#10152E` / `#1E2A5A` | 위는 깊게, 지평선은 밝게 | — |
| `--nt-text` | `#E8EAF6` | 본문 | 13.2:1 |
| `--nt-soft` | `#C3C9E8` | 흐려져도 AA가 남아야 하는 글자 | 9.6:1 |
| `--nt-dim` | `#9AA3CE` | 보조 | 6.4:1 |
| `--star` | `#E8B84B` | 별·화살·강조 — 화면에서 유일하게 따뜻한 색 | 9.0:1 |

### 세 면색이 각자 맡는 것
| 면 | 토큰 | 뜻 |
|---|---|---|
| 크림 | `--bg` `#faf7f0` | 글을 읽는 자리(/about·/careers·법인 정보) |
| 밤 인디고 | `--nt-*` | **회사 정체성** — 겨냥하는 자리 |
| 먹빛 | `--sc-*` `#16151a` | **제품 『탐사대 Z』** — 괴담이 사는 자리 |

셋을 섞지 않는다. 특히 인디고와 먹빛을 같은 검정으로 뭉개면 회사 미학과 게임 미학이
구분되지 않는다 — 그게 이 체계의 요점이다.

### 왜 이 색인가
데브캣 주황·네이버 초록·카카오 노랑·토스 파랑·당근 주황은 이미 임자가 있다.
앰버를 **주색으로** 쓰면 그 대열에 묻히므로 앰버는 점으로만 쓰고, 넓은 면은 인디고가 맡는다.

### 상단바 면색 연동
상단바는 sticky라 어두운 씬 위를 지날 때 크림으로 남으면 화면을 가로지르는 띠가 된다.
`main.js`가 **바 아래 경계(높이+1px)**에 걸린 씬을 매 프레임 판정해 `<html>`에
`bar-night`·`bar-dark`를 붙인다. 바 한가운데로 재면 스크롤 0에서 첫 화면만 크림으로 남는다.

## 9. 페이지 구성

| URL | 내용 | 면 |
|---|---|---|
| `/` | 밤하늘(회사) → 탐사대 Z → ■ 기록 → 분기 → 그 외 프로젝트 | 인디고 → 먹빛 → 크림 |
| `/about/` | 소개·일하는 원칙 4개·연혁 | 크림 |
| `/careers/` | 상시 지원 안내 | 크림 |
| `/privacy.html` | 개인정보처리방침 (noindex) | 크림 |

하위 페이지는 `about/index.html` 꼴의 디렉터리로 둔다 — 확장자 없는 URL이 서버 설정에
기대지 않고 어디서나 동작한다. 자산 경로는 루트 절대(`/style.css`)로 쓴다.

### 배포 시 반드시 하는 것 — 자산 버전 올리기
`index.html`·`about/`·`careers/`·`privacy.html`의 `style.css?v=…`·`main.js?v=…`를 **같이** 올린다.

GitHub Pages는 HTML과 자산 모두 `max-age=600`을 주고 헤더를 바꿀 수 없다. 그래서 새 HTML과
옛 CSS가 만나는 구간이 생긴다 — 실제로 그 상태에서 인트로가 본문 위로 쏟아지고 푸터 마크가
원본 크기로 튀어나오는 사고가 났다. 쿼리 버전이 그걸 막는 유일한 수단이다.
`<head>`의 인라인 `.intro{display:none}` 두 줄은 그래도 뚫렸을 때의 마지막 바닥이다.
